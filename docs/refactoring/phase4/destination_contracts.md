# Phase 4A：Destination 與 filesystem contracts

**PROPOSED / NOT IMPLEMENTED**。本文件定義新 CLI 的授權與 delegate path translation；legacy scripts 保持其現有行為。來源基準與 49 leaves 見 [migration matrix](cli_migration_matrix.md)。

## Roots 與解析

- `R` 是每個 writing invocation 必須明確提供的 absolute authorized output root；其授權不表示可覆寫既有 scientific artifacts。
- `P` 是 navigation publish 的額外顯式 publication root，只有兩個檔案的例外；`V` 在 publish 中是 reviewed preview **read-only input**。
- Preview creation 的完整 output tree 必須寫入 R 之下的 authorized destination V，預設 fresh `R/navigation-preview`。V 在 publish 中是 read-only input。現行架構僅授權兩個 P publication targets 作為 R 外寫入例外。未來任何 R 外 preview proposal 都需要另立 architecture decision、explicit authorization model 與 independent review。
- `L` 是 config case label；`C` 是 resolved source directory basename；`F=fNNNNN`。frame index 與 actual physical time 都要記錄。不要將 L/C 或兩案例的相同 index 當作相同 scientific identity。
- P-refinement output view 明確設 `postproc_root=R/p-refinement/postproc`、`results_root=R/p-refinement/results`；H output view 明確設 `h_refinement_results_root=R/h_refinement`。Input view 保留外部既有 roots，不用 output view 覆蓋 input lookup。
- CLI 路徑依 invocation cwd 轉 absolute；YAML values 依 canonical supplying-file parent。先檢查 lexical traversal/symlink components，再 resolve/檢查 containment；不要先 resolve 掩蓋 alias。

**所有 writing leaves（含 installed dry-run）先取得 mandatory [Filesystem Safety Context](configuration_dependencies.md#mandatory-filesystem-safety-context)**：由 `--paths-config` 或 `NEK_POST_PATHS_CONFIG` resolve 完整原始 machine/input inventory，包含未選 raw cases、historical P/H roots、references/explicit inputs、checkout/installed/native protected ancestors，再檢查 R、各目的地與 P/V。沒有 machine-specific fallback；缺失、不完整、unsafe 或 Unknown plan 一律於 allocation/write-capable handler import 前拒絕。Scientific config 不適用不構成豁免，逐 leaf FS/RO 見 [CLI matrix](cli_migration_matrix.md)。Data-root container 與 file/tree/新 output roles 按 safety context 分別處理，不能把 output view 當保護清單來源。

## Operational write set

僅在 safety preflight 成功後，writing execute/dry-run 的新增 CLI records 才可在以下子樹分配；以 invocation ID 隔離可變 records。native workflow logs/locks 仍在其 native route locations，不搬到此處冒充相同協議。

| Location | Purpose / rule |
| --- | --- |
| `R/.cli/invocations/` | argv、interpreter、captured cwd、resolved inputs/outputs、configuration hashes、environment、status；stdout/stderr 分開 |
| `R/.cli/config/` | Applicable effective absolute-path YAML；hash 變更拒絕，不能覆寫 scientific metadata |
| `R/.cli/cwd/` | Installed child cwd，不能依賴 checkout |
| `R/.cli/tmp/` | Controlled TMPDIR/TMP/TEMP where honored；native same-directory staging 另列 |
| `R/.cli/matplotlib/` | Effective MPLCONFIGDIR 在 pyplot/handler imports 前設定，不能讓 inherited external cache 默默外寫 |
| `R/.cli/locks/` | Supplemental CLI coordination only；不取代 native writer locks |

Help、`--plan`、27 inventory、omega validate、results inventory 不建立上述任何目錄。stdout/stderr 由 caller 外部重導向不等同 CLI 自行建立檔案。Installed dry-run 可寫 operational records，不能執行 scientific children 或調用沒有安全 dry-run 契約的 writer。Native dry-run 的讀取/驗證成本與 purity 各不相同，不作全域承諾。

## Fail-closed safety and limits

Before any allocation/import side effects, resolve/validate the mandatory safety context from the original machine/input view; incomplete inventory keeps the route unavailable. Enumerate products, companion outputs, parent-directory creation, deletes, cache replacement, staging, backups, locks and external-tool outputs. Every resolved actual write must be within R, except the two explicit P targets. Reject unsafe output ancestors, parent traversal, raw-case/historical-result overlap and symlink aliases, including existing path components and dangling links. Protect **all configured raw cases**, not only the selected case. Unknown plan paths cause refusal, not default fallback.

Immutable inputs include snapshots, existing comparison inputs, native manifests and historical scientific artifacts. Overwrite flags apply only to explicitly planned run-owned products and native permitted behavior; they do not authorize historical mutation. CLI containment is supplemental: native `__file__` ancestry, frame-content guards, no-replace operations, resource gates and under-lock revalidation stay authoritative, even if they reject R. Installed roots under native protected installation ancestry require a different output root or a separately reviewed compatibility decision.

Native frames may use Linux renameat2(RENAME_NOREPLACE); PVDs/JSON can have locked replacement rules; catalog publication is exclusive file creation; direct CSV/figure writers can leave partial outputs. Keep those distinctions. Cooperative locks do not protect against hostile concurrent filesystem replacement. No universal transactional, symlink-race-proof or atomic-publication guarantee is made.
